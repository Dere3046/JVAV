# JVAV Calling Convention

The JVAV calling convention defines how functions are called, how arguments are passed, and how registers are managed across function calls. It is used by the JVL frontend compiler and should be followed by hand-written assembly.

> **Version note (v0.3.2+)**: R1–R3 were changed from caller-saved to **callee-saved** to fix register corruption across function calls. As a result, parameter offsets shifted from FP+2 to **FP+5** (FP+0=old FP, FP+1=retaddr, FP+2–FP+4=saved R1–R3).

## Register Roles

| Register | Role | Preserved by |
|----------|------|--------------|
| R0 | Arguments / return value / temporaries | Caller |
| R1–R3 | Arguments / temporaries | **Callee** |
| R4–R5 | Assembler temporaries | Caller |
| R6 (FP) | Frame pointer | Callee |
| R7 | Reserved (backend use) | Neither |
| PC | Program counter | VM |
| SP | Stack pointer | Callee |
| FLAGS | Comparison result flag | Caller |

## Argument Passing

Arguments are passed on the stack using the following protocol:

### Caller responsibilities

1. Evaluate arguments left-to-right
2. Push each argument onto the stack: `PUSH Rarg`
3. Call the function: `CALL func`
4. After the call, clean up arguments: `ADD SP, SP, N`

**Example** (calling `foo(a, b)`):
```asm
    ; Push arguments (right-to-left in stack order)
    PUSH Rb         ; arg 1
    PUSH Ra         ; arg 0
    CALL foo
    LDI R4, 2
    ADD SP, SP, R4  ; remove 2 arguments
```

### Callee responsibilities

#### Prologue

```asm
    PUSH R6         ; save old frame pointer
    PUSH R1         ; save R1 (callee-saved)
    PUSH R2         ; save R2 (callee-saved)
    PUSH R3         ; save R3 (callee-saved)
    MOV  R6, SP     ; establish new frame pointer
    ; optionally allocate locals: SUB SP, SP, locals_count
```

#### Argument access

Arguments are accessed at positive offsets from the frame pointer:

| Location | Offset from FP | Content |
|----------|----------------|---------|
| FP+0 | 0 | Saved old FP |
| FP+1 | 1 | Return address |
| FP+2 | 2 | Saved R1 |
| FP+3 | 3 | Saved R2 |
| FP+4 | 4 | Saved R3 |
| FP+5 | 5 | Argument 0 |
| FP+6 | 6 | Argument 1 |
| FP+7 | 7 | Argument 2 |
| FP+8 | 8 | Argument 3 |

**Example**:
```asm
    ; Access arguments
    LDR R0, [FP+5]   ; arg 0
    LDR R1, [FP+6]   ; arg 1
```

#### Local variables

Local variables are allocated at negative offsets from FP:

```asm
    SUB SP, SP, Rlocal_count   ; allocate locals
    ; local 0 at FP-1
    ; local 1 at FP-2
```

#### Epilogue

```asm
    MOV SP, R6       ; deallocate locals
    POP R3           ; restore R3
    POP R2           ; restore R2
    POP R1           ; restore R1
    POP R6           ; restore old frame pointer
    RET
```

## Complete Function Example

```asm
; Function: int add(int a, int b)
; Arguments: a at FP+5, b at FP+6
; Returns: a + b in R0

add:
    PUSH R6
    PUSH R1
    PUSH R2
    PUSH R3
    MOV  R6, SP
    
    LDR R0, [FP+5]   ; R0 = a
    LDR R1, [FP+6]   ; R1 = b
    ADD R0, R0, R1   ; R0 = a + b
    
    MOV SP, R6
    POP R3
    POP R2
    POP R1
    POP R6
    RET
```

## Stack Layout at Function Entry

```
High addresses
    |
    |    ... caller's stack ...
    |
    |    arg N-1
    |    arg N-2
    |    ...
    |    arg 1
    |    arg 0
    |    return address      <-- pushed by CALL
    |    saved R1
    |    saved R2
    |    saved R3
    +--> saved FP            <-- FP points here
    |
    |    local 0             <-- FP-1
    |    local 1             <-- FP-2
    |    ...
    v
Low addresses
```

## Return Values

- Integer and pointer values: returned in **R0**
- Values larger than 128 bits: not supported by the basic calling convention
- `void` functions: R0 is undefined on return

## Caller-Saved vs Callee-Saved

### Caller-saved registers

The caller must save these registers if their values are needed after a function call:

- R0, R4–R5 (may be clobbered by the callee)
- FLAGS (may be modified by the callee)

**Example**:
```asm
    PUSH R4
    PUSH R5
    CALL some_function
    POP R5
    POP R4
```

### Callee-saved registers

The callee must preserve these registers and restore them before returning:

- R1–R3
- R6 (FP)
- SP (must be restored to its value at function entry)

## Variadic Functions

JVAV does not support variadic functions in the C sense. All functions have a fixed number of parameters known at compile time.

## Syscall Wrapper Convention

Syscall wrappers generated by `.syscall` follow the standard calling convention but additionally:

1. Save arguments to the stack frame
2. Load arguments into the syscall mailbox (`0xFFE1`–`0xFFE3`)
3. Trigger the syscall via `0xFFE0`
4. Read the return value from `0xFFE4` into R0

From the caller's perspective, a syscall wrapper is indistinguishable from a regular function.

## Frame Pointer Usage

The frame pointer (R6/FP) is optional for leaf functions that don't call other functions. However, the JVL compiler always generates frame pointer setup for consistency.

Without FP, arguments and locals are accessed relative to SP, which changes during the function. With FP, the offsets are constant throughout the function execution.

## Stack Alignment

There are no alignment requirements in JVAV because all values are exactly 128 bits (16 bytes). The stack is naturally aligned for all operations.

## Recursion

Recursion is fully supported. Each recursive call creates a new stack frame with its own saved FP, return address, arguments, and locals.

**Example**: Factorial
```asm
    .global _start
_start:
    LDI R0, 5
    PUSH R0
    CALL factorial
    LDI R4, 1
    ADD SP, SP, R4
    HALT

factorial:
    PUSH R6
    PUSH R1
    PUSH R2
    PUSH R3
    MOV  R6, SP
    LDR R0, [FP+5]      ; n
    LDI R1, 1
    CMP R0, R1
    JLE base_case
    
    SUB R0, R0, R1      ; n - 1
    PUSH R0
    CALL factorial
    LDI R4, 1
    ADD SP, SP, R4
    
    LDR R1, [FP+5]      ; n
    MUL R0, R0, R1      ; n * factorial(n-1)
    JMP fact_end
    
base_case:
    LDI R0, 1
    
fact_end:
    MOV SP, R6
    POP R3
    POP R2
    POP R1
    POP R6
    RET
```
